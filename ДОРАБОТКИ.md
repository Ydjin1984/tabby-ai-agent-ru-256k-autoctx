# tabby-ai-agent — форк с доработками (RU + 256K + автоопределение контекста)

> База: `jvit/tabby-ai-agent` v1.0.10 (плагин AI Agent для терминала Tabby).
> Дата форка: 15.09.2026.
> Назначение: локальная модель **Kibborg_Flash_v5.7** (Qwen3.8-27B, llama-server на `http://127.0.0.1:8083`, окно 256K).

---

## Что изменено относительно оригинала

### 1. Автоопределение контекстного окна модели
Плагин сам узнаёт реальное окно у llama.cpp-сервера и подставляет его вместо жёстко заданного числа.

- `src/lib/llm_endpoint.ts` — добавлены `buildPropsUrl()` и `fetchContextWindow()`:
  делают `GET {endpoint}/props` (таймаут 2.5 с) и читают `n_ctx`
  (сначала `default_generation_settings.n_ctx`, затем верхний уровень).
- `src/components/agent_panel.ts` — метод `autodetectContextWindow()` вызывается
  при инициализации панели (`ngOnInit`) и при смене endpoint/модели
  (`applySettingsChange`). Если сервер не отдаёт `/props` (облачные провайдеры),
  остаётся значение из конфига.

### 2. Окно 256K как fallback
- `src/lib/model_presets.ts` — пресет `kibborg`: `contextWindowTokens` изменён
  `131072` → `262144`.
- `config.yaml` (Tabby) — `aiAgent.contextWindowTokens: 262144`.

### 3. В шапке панели показывается модель, а не IP
- `src/components/agent_panel.html` — в `context-bar` вместо `llmEndpoint`
  выводится `config.store.aiAgent.model` (то есть `Kibborg_Flash_v5.7`),
  с fallback на endpoint, если модель не задана.

### 4. Полный перевод интерфейса на русский
Переведены все видимые строки UI, сообщения и описания инструментов:

- `src/components/agent_panel.html` / `agent_panel.ts` — шапка, кнопки, роли,
  статусы тул-коллов (`toolStatusLabel`), плейсхолдеры, ошибки, выводы команд;
- `src/components/agent_settings.html` / `agent_settings.ts` — все секции настроек
  и сообщения проверки endpoint/JSON;
- `src/hotkeys.ts` — названия горячих клавиш;
- `src/toolbar.ts`, `src/decorators/ai_agent.decorator.ts` — кнопка «AI Агент»;
- `src/lib/llm_chat_session.ts` — ошибки сжатия/завершения, стек-трейс;
- `src/lib/ask_user.tool.ts`, `cancel_command.tool.ts`,
  `get_terminal_lines.tool.ts`, `run_shell_command.tool.ts` — описания
  инструментов (уходят в модель) и их выводы.

> Строки выводов тул-коллов переведены согласованно между `agent_panel.ts` и
> `*.tool.ts`, чтобы сопоставление состояний (например
> «Ожидание ввода пользователя в панели агента.») не сломалось.

### 5. Прикрепление файлов и фото (скрепка)
В поле ввода добавлена кнопка-скрепка — можно прикреплять изображения и текстовые файлы.

- `src/lib/llm_chat_session.ts` — `chat()` расширен на `images: string[]`
  (несколько изображений уходят как `image_url` в OpenAI-формате);
- `src/components/agent_panel.ts` — состояние `attachments`, методы
  `openFilePicker` / `onFilesSelected` / `removeAttachment` / `fileToAttachment`,
  чтение файлов через `FileReader` (изображения → data URL, текст → содержимое);
- `src/components/agent_panel.html` — скрепка, скрытый file-input, чипы вложений
  (миниатюра/иконка + кнопка удаления), превью изображений в ленте;
- `src/components/agent_panel.scss` — стили чипов, скрепки, превью.

Правила вложений:
- изображения (png/jpg/gif/webp/bmp/svg, до 15 МБ) → vision (`image_url`);
- текстовые файлы (код, конфиги, логи, CSV и т.п., до 1 МБ) → содержимое в промпт;
- прочие файлы → прикрепляются имя и размер (содержимое не читается).

### 6.4 Ввод текста и диктовка (TypeWhisper / голосовой ввод)

Причина, по которой перестал вставляться текст в поле запроса: комбинация трёх вещей в панели.

1. Поле было отключено во время ответа агента (`[disabled]="sending || …"`) — при нашей медленной локальной модели генерация идёт десятки секунд, и всё это время вставка (в том числе голосовая) физически невозможна. Теперь поле активно всегда; отправку по-прежнему блокирует `canSend` (учитывает `sending`).
2. Панель не ставила фокус в поле: при открытии панели и при клике по пустому месту фокус оставался в терминале, поэтому системная диктовка отправляла текст в шелл (`pwsh.exe`), а не в панель. Добавлено: автофокус при появлении панели (`ngAfterViewInit`), фокус при клике по панели вне интерактивных элементов (`onPanelMouseDown`), фокус после завершения ответа (было и раньше).
3. Вставка многострочного текста могла «отправиться» сразу: `Enter` в обработчике воспринимался как отправка. Теперь `Enter` в течение 300 мс после вставки и во время IME-композиции означает перевод строки.

Дополнительно:
- явный обработчик `paste` (`handleComposerPaste`) сам вставляет текст в позицию каретки (`execCommand("insertText")` с ручным фоллбэком) — не полагаемся на путь по умолчанию, который обходят инструменты диктовки (буфер + синтетический Ctrl+V);
- `Ctrl+Shift+V` и `Shift+Insert` (это хоткей «paste» самого Tabby для терминала) с фокуса в поле вставляют текст в промпт, а не в шелл за панелью.

### 6.5 «Температура» модели: циклы размышлений и бесконечная генерация

Симптом: модель в панели уходила в повторяющийся текст (бесконечный блок «Размышления»), ответа не было.

Диагноз (подтверждён живыми запросами к мозгу):

1. В конфиге Tabby (`aiAgent.additionalRequestParametersText`) лежали `chat_template_kwargs.enable_thinking: true` и `thinking_budget_tokens: 0`. Ноль в llama.cpp означает **безлимитный** бюджет размышлений, а мозг Kibborg запущен с `--reasoning off --reasoning-budget 0`. В результате модель «думает» бесконечно: замер показал `finish_reason=length`, содержимое ответа — 0 символов, reasoning — 3200+ символов. Через шлюз (8083) эти ключи и вовсе не пробрасываются, то есть включение размышлений в UI было ловушкой.
2. Панель не задавала параметры сэмплинга: у локального сервера действовали дефолты `temperature 1.0`, `repeat_penalty 1.0`, `presence_penalty 0`, `frequency_penalty 0` — без защиты от повторов, которая у движка Киборга есть (`0.5 / 0.80 / 20 / 1.5 / 1.05 / 0.2`). Для ternary-модели Bonsai (≈1.7 бита на вес) это прямой путь к циклам.
3. `max_tokens` не передавался → серверный дефолт `-1`, поэтому цикл не обрывался: генерировалось до конца окна.
4. Ветка обработки `finish_reason` не знала про `length` и бросала «Неизвестная причина завершения: length».

Что сделано:

- **Новый модуль** `src/lib/request_defaults.ts`: определяет локальные эндпоинты Киборга (8082–8086, 8090, 8093), вырезает ключи размышлений при работе через шлюз, удаляет «безлимитный» бюджет (`0`/отрицательный) и подставляет параметры движка (`temperature 0.5`, `top_p 0.8`, `top_k 20`, `presence_penalty 1.5`, `repeat_penalty 1.05`, `frequency_penalty 0.2`, `max_tokens 2048`). Значения, заданные пользователем, всегда имеют приоритет; облачные провайдеры не затрагиваются.
- `agent_panel.ts` применяет эту политику последней, после слияния настроек размышлений.
- `llm_chat_session.ts`: `finish_reason: length` разбирается корректно — обрезанный, но непустой ответ возвращается с уведомлением, а «пустой ответ + размышления» вызывает **автоматический повтор запроса без размышлений**; если и он пуст, показывается понятная ошибка вместо падения.
- Подсказка в настройках уровня размышлений предупреждает, что на текущем мозге включение thinking даёт пустой ответ.

Проверка: тесты `request_defaults` (эндпоинты, санитайзинг, приоритет пользовательских значений, облако не тронуто) + живой запрос с исправленными параметрами — `finish_reason=stop`, 1356 символов, повторов нет.

### 6.6 Размышления на прямом мозге (8093): замеры и защита

Пользователь выбрал пресет `kibborg-direct` (8093) с `enable_thinking: true` и `thinking_budget_tokens: 2048`. Замеры на живом мозге показали, что одного бюджета недостаточно:

| Конфигурация | Результат |
| --- | --- |
| бюджет 2048, `max_tokens` 2048, короткая задача | нормально: reasoning 1008 симв., ответ 362, `finish=stop` |
| бюджет 2048, `max_tokens` 2048, длинная задача (план) | **ответ пустой**: reasoning 7015 симв., `finish=length` |
| бюджет 2048, `max_tokens` 4096, та же задача | ответ 7025 симв., но снова обрезка и первые повторы |
| бюджет 2048, `max_tokens` 6144, та же задача | ответ 15 486 симв., 198 секунд, всё ещё обрезка и повторы |

Вывод: эффективный бюджет размышлений не следует строго за запрошенным значением, а модель склонна «растекаться». Поэтому в расширении:

- `THINKING_ANSWER_RESERVE_TOKENS = 4096` — при включённых размышлениях `max_tokens` автоматически поднимается до «бюджет + 4096» (пользовательское большее значение не понижается);
- `LOCAL_THINKING_BUDGET_LIMIT = 4096` — уровень «Максимальный» (16384) на локальном мозге ограничивается, иначе генерация идёт минутами;
- `looksRepetitive(text)` — детектор цикла по доле повторяющихся строк;
- в `llm_chat_session`: обрезка по лимиту (`finish_reason: length`) теперь разбирается по-человечески — нормальный длинный ответ возвращается с уведомлением, а пустой или зацикленный **отбрасывается** (`onDiscardDraft` очищает черновик в панели) и запрос повторяется один раз без размышлений с уведомлением в ленте.

Практическая рекомендация: на текущем мозге (Bonsai 2 27B, тернарные веса, сервер запущен с `--reasoning off`) размышления заметно замедляют ответ и склонны к длинным «простыням» — для сложных задач надёжнее держать уровень «Выключено»; короткие задачи на «Среднем» работают.

### 6.7 Итоговые замеры: нужны ли вообще размышления на локальных моделях

Одна и та же задача (однострочник PowerShell) на всех конфигурациях, `max_tokens` 4096:

| Конфигурация | Время | reasoning | Ответ | Качество команды |
| --- | --- | --- | --- | --- |
| **8093, Выключено** | **3.1 с** | 0 | 399 симв. | верно: `Get-ChildItem -Recurse -ErrorAction SilentlyContinue … Sort-Object Length -Descending … Select-Object -First 10` |
| 8093, Низкий (1024) | 13.8 с | 1926 | 322 симв. | верно |
| 8093, Средний (2048) | 23 с | 3668 | 279 симв. | **сломано**: выдуманный командлет `Select-First 10` |
| **8086, Выключено** | **1.8 с** | 0 | 373 симв. | верно |
| 8086, Средний (2048) | 28.7 с | 6616 | 573 симв. | невалидно: `-ExpandProperty FullName, Length` (два свойства) |

Вывод: на локальных моделях размышления **дороже в 7–16 раз и не дают более точного ответа** — модель тратит бюджет на рассуждения и всё равно ошибается в синтаксисе. Рабочий режим для локального стека — «Выключено»; уровень «Низкий» допустим, если очень хочется размышлений. Облачные модели (DeepSeek) обучены под `reasoning_effort`, там уровни осмысленны.

## Сборка

```powershell
cd <путь к клону репозитория>
npm install        # зависимости НЕ входят в архив (восстанавливаются)
npm run build      # webpack → dist/index.js
```

## Установка в Tabby

```powershell
Copy-Item .\dist\index.js "$env:APPDATA\tabby\plugins\node_modules\tabby-ai-agent\dist\index.js" -Force
Copy-Item .\dist\index.js.map "$env:APPDATA\tabby\plugins\node_modules\tabby-ai-agent\dist\index.js.map" -Force
```

После копирования — полностью перезапустить Tabby.
